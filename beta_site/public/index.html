Check a neurodata release locally before sharing it

NeuroData Release Security Audit checks release structure and bounded metadata for privacy-relevant patterns. It creates reports on your computer without uploading or modifying the dataset.

Download and start

  1. Download and unpack the beta archive.
  2. Open README_EN.md and install the wheel in a separate Python environment.
  3. Run the included synthetic demo, then optionally scan a dataset you are authorised to use.
  4. Open the HTML report and assess whether the result and next actions are clear.
  5. Complete FEEDBACK_EN.md. Send feedback, not the dataset.

Installing optional readers normally downloads dependencies from the package index. The dataset scan itself is local. Unsupported or unreadable objects remain visible as coverage gaps.

Confirm the installation

After installing the downloaded wheel, run:

neurodata-security-audit --version

The command should print the beta version.

Interpret the command and report

The command exit status describes whether the scan completed and whether it found a high-priority item. It is not a release decision.

  • Exit 2 · STOP: the scan, integrity check, or report writing failed. Do not use the report as a release decision.
  • Exit 1 · HOLD: the scan completed and at least one high-priority finding requires review before release.
  • Exit 0 · NOT APPROVED: the scan completed without a high-priority finding. Review findings, coverage gaps, and format limits still require a human decision.

The HTML report separately summarises the curator decision. It may display HOLD for unresolved review findings or coverage gaps even when the command exits with status 0. The local interface may describe the same state as Review required. These conservative report labels do not indicate a failed scan, and none of them approves release.

Data and privacy boundary

The scanner does not send dataset files, local paths, or report contents to this site. The site stores a random download-session identifier, release version, and timestamps for download and optional installation confirmation. The random identifier and release version are also kept in this tab's sessionStorage so confirmation can recover after a refresh; they are cleared after confirmation or when the tab session ends.

A daily cleanup deletes database records older than 30 days. If a scheduled cleanup is delayed, records remain until the next successful cleanup. No IP address, browser fingerprint, account, or participant identifier is stored in this database.

Cloudflare processes ordinary network connection metadata to serve the page. Invocation logs are disabled for this Worker. Review reports manually before sharing them, because a report can still contain project-specific filenames or context.

Important

The audit identifies items that need human attention. It does not prove anonymity, estimate re-identification risk, approve publication, or provide privacy, security, ethics, or legal certification.
