Run it on your own dataset

  1. Download and unpack the beta archive.
  2. Open README_EN.md and install the wheel with the optional readers needed for your file formats.
  3. Start the local interface with neurodata-security-audit ui.
  4. Select a dataset you are authorised to use and a new report folder outside that dataset.
  5. Open the generated HTML report and assess whether the findings, coverage, and next actions are clear.
  6. Complete FEEDBACK_EN.md. Send feedback, not the dataset.

No suitable dataset at hand? The included synthetic demo is an optional installation check. It deliberately contains privacy-relevant metadata and returns HOLD.

Open feedback email

This opens your email app; nothing is sent automatically. Paste the completed FEEDBACK_EN.md into the message. Do not attach the dataset or an unreviewed report.

Interpret the command and report

1. Did the scan complete?

  • Exit 2 · STOP: the scan, integrity check, or report writing failed.
  • Exit 1 or 0: the scan completed; continue to the report.

2. What needs review?

  • HOLD / Review required: resolve high-priority findings, review findings, or coverage gaps.
  • NOT APPROVED: no high-priority finding was detected, but a human must still review all findings, coverage, and format limits.

The command exit status describes execution and high-priority findings; the HTML report separately summarises the curator decision. A report may display HOLD even when the command exits with status 0. None of these labels approves release.

Data and privacy boundary

Your dataset stays on your computer.

The scanner does not send dataset files, local paths, or report contents to this site. The site stores a random download-session identifier, release version, and timestamps for download and optional installation confirmation. The random identifier and release version are also kept in this tab's sessionStorage so confirmation can recover after a refresh; they are cleared after confirmation or when the tab session ends.

A daily cleanup deletes database records older than 30 days. If a scheduled cleanup is delayed, records remain until the next successful cleanup. Download attempts are capped per Cloudflare location to reduce automated counter inflation. No IP address, browser fingerprint, account, or participant identifier is stored in this database.

Cloudflare processes ordinary network connection metadata to serve the page. Invocation logs are disabled for this Worker. Review reports manually before sharing them, because a report can still contain project-specific filenames or context.
