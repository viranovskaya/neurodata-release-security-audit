# v0.2 scope

## Question

v0.2 asks:

> What is present in this local release, which metadata was checked, and which
> files or references still need a manual decision before sharing?

It does not ask whether every participant is anonymous. That would require
format-specific de-identification, statistical disclosure analysis and, for imaging,
pixel or voxel review.

## Threat model

The intended user is an honest researcher or data manager who may have left direct
identifiers, technical metadata, old references or unwanted files in a release.

The scanner protects against accidental disclosure and common release-tree mistakes.
It is not designed to open hostile files safely, detect malware, defeat filesystem
races controlled by an attacker or certify legal compliance.

## Release-wide accounting

Every encountered filesystem entry receives one coverage status. Every readable
regular file receives a size and SHA-256 digest.

The scanner checks file hashes and the release-tree structure again after metadata
inspection. A changed, added or removed entry produces a review finding. Symlink
targets are compared without following them. This is a consistency check for the
local run, not a signed or trusted manifest.

## Metadata readers

### Text and BIDS

Small text and structured JSON, TSV, CSV and XML files are checked for supported
personal and technical fields. BIDS `IntendedFor`, `AssociatedEmptyRoom`, `Sources`
and `RawSources` references are resolved when they describe local files.

### EEG

- BrainVision text metadata and internal file references;
- EDF and BDF common headers;
- FIF metadata through MNE;
- continuous EEGLAB metadata plus external data references;
- EGI MFF metadata and bounded XML.

MNE readers use signal preloading disabled. A reader that returns preloaded data
fails visibly.

### NIfTI

Nibabel opens `.nii`, `.nii.gz` and paired `.hdr` metadata with `mmap=False` and
`keep_file_open=False`. The scanner checks text-bearing header fields but never
requests `dataobj` or a voxel array. Paired `.img` files are treated as image
payloads.

NIfTI extensions are reported but not interpreted.

### DICOM

Pydicom uses `stop_before_pixels=True`, `force=False` and deferred large values.
The scanner checks supported patient, date, staff, institution, device, UID,
demographic and free-text elements in file metadata and nested sequences.

Private tags are reported without reading their values. Encapsulated documents and
pixel elements are not opened by the audit walker. Metadata after the first Pixel
Data element is outside this reader.

`BurnedInAnnotation`, recognizable visual features and a statement that patient
identity was not removed are high-severity release stops. They still require a
separate image workflow.

## Archives

ZIP and TAR directory entries are listed without extraction. The report includes
member names, types and declared sizes, and detects:

- encrypted ZIP members;
- nested archives;
- absolute or parent-traversing paths;
- links and special filesystem entries;
- duplicate and case-colliding member names;
- unusual declared expansion size or compression ratio.

Archive member payloads are not opened or searched. RAR, 7z, `.tar.zst`, plain gzip
and encrypted payloads remain manual-review boundaries.

## Cross-file references

The scanner checks supported BrainVision, EEGLAB and BIDS links without following
external paths or symlinks. Each link is classified as:

- valid internal;
- missing;
- external;
- through a symlink;
- wrong case;
- not a regular file.

Duplicate basenames are informational. Case-colliding paths or basenames need review
because they behave differently across filesystems.

## Reports

JSON and Markdown output is deterministic for a stable release tree. Detected values
are masked. Known terms, contacts, dates, credentials and common local or network
paths are also masked when they appear in report paths.

Unrecognised identifying text can still remain in a filename. Reports are working
review artifacts and should be checked before sharing.

## Explicit non-goals

v0.2 does not:

- prove anonymity or compliance with GDPR, HIPAA or an ethics protocol;
- assess biometric re-identification from EEG, MRI or other signals;
- perform defacing, OCR, face detection or visual inspection;
- measure uniqueness or linkage risk in participant tables;
- modify, redact or delete source data;
- extract or decrypt archives;
- inspect cloud storage, databases or remote services;
- analyse malware or adversarial files.

## Local release gate

The integrated candidate can move to independent review only when:

- every release entry has one coverage record;
- all readable regular files are in the manifest;
- file and tree rechecks pass;
- no signal, voxel, pixel or archive-member payload is loaded by a metadata reader;
- base, EEG-format and imaging environments pass the full suite;
- Python 3.10 and the newest supported Python pass;
- JSON matches the published schema;
- wheel and demonstration reports are deterministic;
- public-data calibration and source-integrity checks are recorded;
- the worktree is clean and the candidate commit is frozen.
